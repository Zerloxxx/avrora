# ADR-0007: Расширения схемы cosmo-A-1.0 — маска горизонта, наклонение плоскости, произвольные очереди

Status: accepted
Date: 2026-09-12

## Context

Организатор на консультации назвал главной задачей «правильную геометрию» и попросил: (1) учитывать рельеф и застройку вокруг пунктов; (2) дать проектировщику менять конфигурацию запуска — число плоскостей, «оси» (наклонения), число и состав очередей, не только 3 × 16; (3) чтобы всё это считала сама модель. Схема `cosmo-A-1.0` этого не описывает: наклонение общее в `environment`, `launch_batch` в кейсе 1–3, у пункта только широта/долгота.

Варианты:
1. Своя схема `cosmo-B` — чисто, но файл жюри перестанет быть «тем же форматом», а обязательный пункт ТЗ — загружать их JSON и выгружать такой же.
2. Расширить `cosmo-A-1.0` **необязательными** полями: старые файлы читаются без изменений, новые поля появляются в экспорте только если заданы.
3. Хранить расширения вне файла (localStorage) — теряются при передаче, не сравниваются.

## Decision

Вариант 2. Необязательные поля, все игнорируются `geometry.py` без ошибок:
- `ground_sites[].horizon_mask` — массив углов закрытия (градусы) по секторам азимута от севера по часовой (36 секторов по 10°; допустимо ≥ 4); `terrain` — источник (`village`/`city`/…/`dem`/`custom`), `terrain_source`, `h0_m` — для отчёта.
  Правило видимости: возвышение ≥ `max(min_elevation_deg, horizon_mask[сектор])`. Без поля — ровно правило кейса.
- `design.planes[].inclination_deg` — наклонение плоскости; без поля — `environment.inclination_deg`.
- `launch_batch` — любое целое ≥ 1; `launch_stage` — от 1 до максимальной очереди. Файлы кейса (1–3) — частный случай.

Источники маски: пресеты застройки (высота/расстояние → `atan`), реальный рельеф (ASTER GDEM 30 м через OpenTopoData — предрасчёт скриптом `tools/horizon-mask.py` в `data/terrain.js` для пунктов кейса и городов из списка; Copernicus DEM GLO-90 через open-meteo — по кнопке из браузера), ручная маска. Формула одна — `maskFromProfiles()` в `sim.js`, скрипт её дублирует.

Конструктор группировки — генератор Walker T/P/F с веером RAAN (180° Star / 360° Delta), кейс воспроизводится как 48/3/1, веер 180° (тест). Подбор проекта — перебор Walker-конфигураций на грубой сетке в воркере.

## Consequences

- Файл жюри загружается и выгружается без изменений; наши поля попадают в экспорт только когда проектировщик их задал. `check`/сверка с `geometry.py` остаётся валидной для файлов без расширений.
- «Маска 0 ⇒ результат совпадает с правилом кейса» и «Walker 48/3/1 = кейс» закреплены тестами — расширения не могут незаметно сломать эталон.
- OpenTopoData не отдаёт CORS → из браузера используется open-meteo (другой DEM, 90 м); в отчёте источник пишется явно.
- Интерфейс перестал предполагать 3 очереди: кнопки этапов, план развёртывания, состав очередей и сравнение строятся от `maxBatch()`.
