# Архитектура «Авроры»

Статический веб-сервис без бэкенда: расчёт, интерфейс и 3D-сцена работают в браузере. Причины — ADR-0001.

Две страницы на одном домене и одном ядре: **инженерный вид** (`index.html`) для проектировщика и
**вид абонента** (`abonent/index.html`, ставится на экран «Домой» в Safari) для жителя пункта — ADR-0008.
Конфигурация передаётся между ними ссылкой `#c=`, а при открытых обоих окнах инженерный вид ведёт
время и скорость абонента через `BroadcastChannel` — ADR-0009. Числа на страницах совпадают по построению.

## Схема

```
 index.html ─┬─ data/scenarios.js   (window.SCENARIOS — 4 сценария кейса, сгенерировано tools/bundle-scenarios.py)
             ├─ data/terrain.js     (window.TERRAIN — маски горизонта по DEM, сгенерировано tools/horizon-mask.py; необязателен)
             └─ src/app.js  (точка входа: DOM-события → модель/сцена/аналитика; старт цикла)
                   │
     ┌─────────────┼──────────────────────┬───────────────────────┐
     ▼             ▼                      ▼                       ▼
 model.js       panels.js             analysis.js            scene.js
 мутации state  левая/правая панель,  окно «Аналитика»,      Three.js: Земля, спутники,
 + события      сравнение вариантов   отчёт, инструменты     оверлей, камера, главный цикл
     │                 ▲                    │    ▲                  ▲
     │  emit()         │ on()               │    │ on()             │ on()
     └────────► state.js (state, шина событий, DOM-хелперы, форматирование) ◄──┘
                                            │
                                      tools.js ──► worker.js ──► sim.js
                                      (runTask)   (в фоне)      расчётное ядро
                          sim.js импортируется напрямую в model/scene/panels/analysis для быстрых расчётов
```

## Модули (`web/src/`)

| Модуль | Ответственность | Импортирует |
|---|---|---|
| `sim.js` | Чистые функции: позиции (наклонение на плоскость), местная система пункта и маска горизонта, снимок сети, маршрут (липкий BFS), доступность за сутки, валидация, оптимизаторы, покрытие, N-1/N-2, Монте-Карло, резерв, генератор Walker и подбор проекта. Ни DOM, ни state. Тот же код работает в воркере и в `node --test`. | — |
| `state.js` | Единственный объект `state`, шина событий (`emit`/`on`), `$`/`$$`, `toast`, форматирование, `drawStrip`, шкала `heat`. | — |
| `model.js` | Все изменения конфигурации: загрузка, правки параметров, отказы, пункты, варианты, импорт/экспорт, ссылка. Публикует события, DOM не трогает (кроме `toast`). | state, sim |
| `scene.js` | Сцена и главный цикл: каждый кадр считает `snapshot` на текущее время, рисует, отдаёт экранные координаты спутников для hover. Подписан на `scenario` / `scene:rebuild`. | state, sim, three |
| `panels.js` | Представления боковых панелей и окна сравнения. Подписан на `scenario` / `controls` / `recomputed` / `variants`. | state, sim, model |
| `analysis.js` | Окно «Аналитика»: запуск инструментов через `tools.js`, отрисовка результатов, отчёт. Подписан на `recomputed`. | state, sim, model, scene, tools |
| `tools.js` | Один воркер на расчёт, прогресс, блокировка кнопок, сохранение результата в `state.analysis[type]`. | state |
| `worker.js` | Диспетчер `type → функция sim.js` в Web Worker. | sim |
| `app.js` | Привязка DOM-событий, старт. Логики нет. | все |
| `globe.js` | Общие ресурсы 3D: текстуры Земли и атмосфера, звёзды, модель аппарата, `toThree`, `makeProjector`. Ни DOM, ни state. Пути к ресурсам — от модуля (`import.meta.url`). | three |
| `configlink.js` | Формат ссылки `#c=`: `encodeDiff` / `decodeDiff` / `applyDiff` / `readHash`, включая рельеф (`hm`), наклонение плоскости и пересобранный `design` (`dz`). Общий для обеих страниц. | — |
| `sync.js` | Связь двух видов в одном браузере (`BroadcastChannel`): `startBroadcaster` для инженерного вида, `startFollower` для абонента. Без сервера — ADR-0009. | — |
| `subscriber.js` | Вся страница абонента: своя сцена из `globe.js`, окна связи, небо над пунктом (в том числе закрытые рельефом), геолокация. Плоский локальный `S`, без шины. | sim, globe, configlink, sync, state, three |

## Поток данных

1. `loadScenario(raw)` → `state.base`, `state.scenario` → `recompute()` → `computeAvailability` (≈40 мс на сутки, замеры — в `web/CLAUDE.md`) → событие `recomputed` → панель «Доступность», вкладка «Качество».
2. Правка в форме → `model.setX()` → `markChanged()` → (`scene:rebuild`, если менялась геометрия) → через 120 мс `recompute()` + `controls`.
3. Каждый кадр `scene.js`: `snapshot(scenario, t)` → `findRoute(prev)` → рендер → `renderStatus()`.
4. Тяжёлое (оптимизаторы, матрица пар, Монте-Карло, покрытие) → `runTask` → воркер → прогресс → результат в `state.analysis` → рендерер вкладки.
5. Сохранение варианта копирует `scenario` + сводку показателей; сравнение и отчёт читают только сохранённые данные.

6. Вид абонента: `#c=` → `decodeDiff` + `applyDiff` на копию встроенного сценария → `computeAvailability` +
   `contactWindows` для выбранного пункта → статус «связь есть/нет», расписание окон, небо. Время модели по
   умолчанию берётся от текущего UTC, а не от полудня: жителю нужен ответ «когда», а не красивая освещённость.
7. Синхронизация: инженерный вид шлёт такт `{t, playing, speed}` 4 раза в секунду и `#c=`-дифф при изменении
   конфигурации → абонент переходит в режим «ведомый», доигрывая время между тактами. Ручное отцепление
   (`detached`) сильнее такта. Ведомых видно по точке у пункта «Вид абонента» в шапке.

## События шины

| Событие | Кто публикует | Кто слушает |
|---|---|---|
| `scenario` | `loadScenario`, `openVariant` | panels (перерисовать всё), scene (пересобрать объекты), analysis (чекбокс тени) |
| `recomputed` | `recompute` | panels (доступность), analysis (качество, сброс устаревшей карты покрытия) |
| `controls` | `markChanged` после пересчёта | panels, analysis |
| `scene:rebuild` | `markChanged({rebuildScene})` | scene |
| `variants` | `saveVariant`, `deleteVariant` | panels |

## Инварианты

- Вся физика — в `sim.js`; проверка против `geometry.py`: на `t=0` полной группировки 76 ISL-рёбер и маршрут C65 → S20 → G_MUR (тест `tests/sim.test.mjs`).
- Расчётная сетка одна: `timeGrid()` — отсчёты 0 … `horizon_s − step_s` (720 штук, правый конец не включается). Сцена привязывает время к сетке перед снимком, чтобы совпадать с диаграммой и с выгрузкой `routes`.
- Расстояния в километрах везде; в сцене единица — радиус Земли, орбита визуально приподнята в 1.42 раза (ADR-0004).
- Время модели у абонента имеет три режима: ведомый (`follow`), живой UTC (`live`) и ручная перемотка. Подпись под часами обязана говорить, какой активен.
- Системы координат: ECEF/инерциальная с осью Z на север (как в `geometry.py`) ↔ Three.js с осью Y вверх: `toThree(p) = (p.x, p.z, −p.y)`.
