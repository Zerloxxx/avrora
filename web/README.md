# Аврора — папка сервиса

> **Полное описание сервиса — в корневом [`../README.md`](../README.md):** идея, расчётная модель,
> маршрутизация и её обоснование, архитектура, форматы данных, воспроизводимые числа, демо-сценарий
> и соответствие критериям оценки. Здесь — только то, что нужно, когда работаешь внутри `web/`.

Статичный прототип (HTML/CSS/JS без сборки). Расчёт положений спутников,
ISL-связей и видимости с земли — порт `Расчетный модуль/geometry.py` на JS,
маршрут строится «липким» BFS-ом от клиентского пункта до шлюза (ADR-0003).

3D-сцена — Three.js r160, Земля — текстуры NASA Blue Marble (4096px день, облака,
ночные огни, карта высот, блики океана). Библиотека и текстуры лежат в `vendor/`,
интернет для показа не нужен (кроме шрифтов Google Fonts — есть системный fallback).

Спутники — процедурная модель (корпус в ЭВТИ, панели солнечных батарей, тарелка в надир).
Чтобы подставить настоящую 3D-модель, положите glTF-файл в `vendor/satellite.glb` —
он подхватится автоматически и отмасштабируется.

## Запуск

```bash
cd web && python3 tools/serve.py
```

- http://localhost:8765 — **инженерный вид** (проектирование группировки);
- http://localhost:8765/abonent/ — **вид абонента** (что связь значит для жителя пункта).

ES-модули не работают через `file://` — нужен HTTP-сервер. `tools/serve.py` — обычный `http.server`
плюс `Cache-Control: no-store`: без него браузер кеширует ES-модули и после правки кода страница грузит
прежнюю версию. Подойдёт и `python3 -m http.server 8765 --directory web`, и `web/start.bat` (Windows) /
`web/start.sh` (macOS, Linux) — просто при разработке чистите кеш.

## Тесты

```bash
node --test
```

39 тестов проверяют расчётное ядро против эталона `geometry.py` (76 ISL-связей и маршрут C65 → S20 → G_MUR на t=0;
полное совпадение множества рёбер на 12:00 — если установлены Python и NumPy), сетку из 720 отсчётов,
доступность по сценариям, «липкую» маршрутизацию, сравнение стратегий, резервные пути,
валидацию файла, отпечаток конфигурации, рельеф, конструктор Walker и инструменты анализа.

## Рельеф вокруг пунктов (необязательно)

Маски горизонта для пунктов кейса и городов из списка уже посчитаны (`data/terrain.js`, ASTER GDEM 30 м). Пересчитать или добавить точку:

```bash
python3 web/tools/horizon-mask.py            # все пункты кейса и города → data/terrain.js
python3 web/tools/horizon-mask.py 71.64 128.87   # одна точка → JSON в stdout
```

Нужен интернет (OpenTopoData, ~1 запрос/с). В интерфейсе для любого пункта можно выбрать пресет местности
(посёлок / город / горная долина …) или запросить рельеф по кнопке (open-meteo, Copernicus DEM 90 м).

## Обновить встроенные сценарии

После изменения файлов в папке «Данные»:

```bash
python3 web/tools/bundle-scenarios.py
```

## Сверка с эталоном организаторов

```bash
node tools/parity.mjs
```

Гоняет `geometry.py` на всех четырёх сценариях в пяти моментах времени и сравнивает позиции, признак
активности, множество ISL-рёбер и видимость с пунктов. Текущий результат — расхождений нет, позиции
совпадают до 1e-10 км.

## Вид абонента

Вторая страница того же сайта и того же расчётного ядра — для человека в наземном пункте, а не для
проектировщика. Показывает: есть ли связь сейчас и сколько продлится, расписание окон связи на сутки,
через какой аппарат идёт трафик и с какой задержкой, какие спутники над головой (сторона света, угол
над горизонтом и отдельно те, что **закрыты рельефом**), сколько связи за сутки и самый длинный перерыв.

- **Связь с инженерным видом.** «Выгрузить → Скопировать ссылку для абонента»: ссылка несёт текущую
  конфигурацию (этап, RAAN, фазы и наклонения, отказы, пункты, маски рельефа), поэтому числа на телефоне
  совпадают с таблицей на основном экране. Обратная ссылка — «Инженерный вид →» в шапке.
- **Установка на телефон.** Открыть `/abonent/` в Safari на iOS → «Поделиться» → «На экран «Домой»».
  Запускается без адресной строки, со своей иконкой. После первого открытия работает без сети —
  для северного пункта это основной режим.
- **Свой пункт.** Кнопка «Моё местоположение» добавляет фактические координаты телефона как новый
  клиентский пункт и считает доступность для него (нужны HTTPS и разрешение браузера).

### Оба вида в такт

Если инженерный вид и вид абонента открыты в одном браузере, второй идёт за первым: время, скорость
(×1 / ×4 / ×16), пауза и конфигурация. Переключили этап, задали отказ или сменили местность — статус
жителя меняется сразу. Под часами написано «инженерный вид · ×16», а точка у пункта «Вид абонента»
в шапке показывает докладчику, что связь есть.

- Житель отцепляется кнопкой «Сейчас» и возвращается кнопкой «За инженером».
- **Работает только между окнами одного браузера на одной машине** — это `BroadcastChannel`, без сервера.
  Ноутбук и настоящий телефон так не связать; на отдельных устройствах оба вида и так показывают один
  момент, пока идут по живому UTC. Подробнее — ADR-0009.
- Для показа держите оба окна видимыми: в фоновой вкладке браузер останавливает отрисовку.

Почему страница, а не нативное приложение — ADR-0008.

## Структура

- `index.html`, `style.css` — разметка и стили;
- `src/sim.js` — расчётное ядро (порт `geometry.py`): позиции, ISL, видимость с маской горизонта, маршрут, доступность,
  валидация, автоподбор, покрытие, N-1/N-2, Монте-Карло, резерв, Walker-генератор и подбор проекта; без DOM, работает в воркере и тестах;
- `src/model.js` — изменения конфигурации, варианты, импорт/экспорт, ссылка на конфигурацию;
- `src/scene.js` — Three.js: Земля, спутники, оверлей, камера, главный цикл;
- `src/panels.js` — боковые панели и окно сравнения;
- `src/analysis.js` — окно «Аналитика» и отчёт; `src/tools.js` + `src/worker.js` — фоновые расчёты;
- `src/state.js` — состояние, шина событий, хелперы; `src/app.js` — привязка событий и старт;
- `tests/` — тесты ядра (`sim.test.mjs` — эталон и ТЗ, `design.test.mjs` — рельеф и конструктор); `tools/` — сборка сценариев, маски рельефа; `data/` — встроенные сценарии и маски; `vendor/` — Three.js и текстуры.

Схема и поток данных — `../docs/ARCHITECTURE.md`; решения — `../docs/adr/`; термины — `../CONTEXT.md`.
