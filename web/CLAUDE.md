# web/ — знания фронтенда и расчётного ядра

Общее о проекте — в корневом `CLAUDE.md`, термины — в `CONTEXT.md`, схема модулей — в `docs/ARCHITECTURE.md`. Здесь — то, что не выводится из кода: паттерны, грабли, договорённости.

## Запуск и проверка

- Локально: `cd web && python3 tools/serve.py` — тот же http.server, но с `Cache-Control: no-store`.
  **Через `python3 -m http.server` браузер кеширует ES-модули:** после правки `src/*.js` страница грузит прежнюю
  версию модуля и падает с «does not provide an export named …», хотя код уже верный. Час потерян на это — не повторять.
  Простой вариант тоже работает: `python3 -m http.server 8765 --directory web` (или `web/start.bat`, `web/start.sh`).
  `file://` не работает — ES-модули и воркер. На macOS бинарника `python` нет, только алиас zsh: везде `python3`.
  На Windows наоборот: `python3` — заглушка Microsoft Store (процесс падает с кодом 9009), работает `python`.
  Поэтому `.claude/launch.json` (сервер для панели предпросмотра) — локальная настройка: на Windows там `python`,
  на macOS `python3`; в git лежит вариант для macOS, правку под свою машину не коммитить.
- Вид абонента: http://localhost:8765/abonent/ — вторая страница того же сайта (ADR-0008).
- Синхронизацию видов проверять в **двух видимых окнах**: `requestAnimationFrame` не тикает в фоновой вкладке,
  поэтому у скрытой страницы данные приходят, а картинка и подписи замирают — это не баг.
  Состояние ведомого смотреть через `window.S` (`follow`, `detached`, `speed`), а не по DOM скрытой вкладки.
- Полная сверка с эталоном: `node tools/parity.mjs` — `geometry.py` на 4 сценариях × 5 моментов, сравниваются
  позиции, `active`, ISL-рёбра и видимость. **`edges` в выводе `geometry.py` — это ISL плюс наземные линии**
  (на t=0 полной группировки 86 = 76 ISL + 10 наземных); сравнивать с `snap.isl` напрямую нельзя.
- Тесты ядра: `cd web && node --test`. Эталон — `geometry.py`: 76 ISL и маршрут C65 → S20 → G_MUR на `t=0` полной группировки.
- Быстрая отладка в консоли: `window.state`, `window.__scene = {camera, dyn, root, inertial}`.
- Публикация в артефакт claude.ai: страница без `<html>/<head>/<body>` собирается скриптом `mkpub.py` (в scratchpad агента) из `index.html`; поддерживающие файлы — `src/**`, `style.css`, `data/scenarios.js`, `vendor/**`.

## Паттерны

- **Новая функция анализа**: чистая функция в `sim.js` (принимает `scenario`, `{ stepMul, onProgress }`) → запись в `TOOLS` в `worker.js` → рендерер `renderX(result, out)` в `analysis.js` → кнопка в `index.html` → обработчик в `app.js` через `runAnalysis(type, opts, '#out', renderX)`. Результат автоматически попадает в `state.analysis[type]` и в отчёт.
- **Изменение конфигурации** — только через функции `model.js` (`setStage`, `setPlaneParam`, `addOutage`, `addSite`, …), которые зовут `markChanged()`. Прямая мутация `state.scenario` из представления — ошибка: не будет пересчёта и перерисовки.
- **Геометрия сцены меняется** (плоскости, состав спутников) → `markChanged({ rebuildScene: true })`; иначе орбиты останутся старыми.
- **Грубая сетка `stepMul`** — только внутри переборов (оптимизаторы, N-2, Монте-Карло, покрытие). Всё, что показывается пользователю как итог, считается на полной сетке.
- **Прогресс** тяжёлых расчётов: `onProgress(done, total)` вызывать не чаще чем раз в ~20 итераций — `postMessage` на каждый шаг заметно тормозит воркер.
- **Долгие функции кладут `stepMul` по умолчанию** так, чтобы расчёт оставался в секундах на 48 КА (N-2: `stepMul=3`).
  Замеры: N-1/N-2 ~14 с, `optimizePlanes` ~18 с (он на полной сетке — самый долгий), остальное ≤4 с;
  полный список — в «Договорённостях по данным» ниже. Новый инструмент калибровать по этим цифрам,
  а не по «5–8 с», как было написано раньше.

## Визуальный язык (скиллы `frontend-design` от Anthropic и `ui-ux-pro-max`, оба в `~/.claude/skills`)

- Один акцент — сцена с Землёй; интерфейс вокруг неё тихий: стеклянные панели, тонкие линии, без карточек-плашек с тенями. Цвет несёт смысл (маршрут — золотой, отказ — красный, шлюз — жёлтая подпись/пунктир), остальное нейтральное; главная кнопка — сплошной `--accent`, градиентов в интерфейсе нет.
- Шрифты: `Unbounded` (заголовки, крупные числа) + `Golos Text` (текст) — обе с родной кириллицей, выбраны вместо Inter намеренно; подключены с Google Fonts на обеих страницах, fallback системный. Заголовки разделов — `Unbounded` 12px обычным регистром. **Не** возвращать капс с разрядкой, эмодзи/юникод-глифы вместо иконок, мета-строки «A · B · C», градиентный текст — это «улики сгенерированного интерфейса» из скилла.
- Иконки — спрайт `<svg hidden>` в начале `index.html` (`#i-play`, `#i-x`, `#i-plus`…), вставка `<svg class="ic"><use href="#i-x"/></svg>`; у кнопок-иконок обязателен `aria-label`. Play/pause переключается классом `.playing` на `#btn-play`, а не текстом.
- Показатели — сеткой «подпись — значение» (`.avail-row .kv`), числа `tabular-nums`; цифры крупно только в `.stat`/`.kpi` (левая линия вместо фона).
- Формы — видимые подписи `label.field` над полем (не placeholder-only); пустые списки объясняют, что делать (`:empty::before`).
- Точки адаптива: ≥1800 — панели 340px; 1101–1360 — 272px; ≤1100 — панели по одной поверх сцены кнопками в шапке (`body.show-left/.show-right`), навигация уходит в меню `#btn-menu`, кнопки шапки становятся иконками (`.only-narrow/.only-wide`); ≤720 — панели как шторка снизу над таймлайном, модальные окна во весь экран (`100dvh`), вкладки аналитики прокручиваются, таблицы `.cmp` — горизонтальный скролл; ≤420 — без выбора скорости. Тап по сцене закрывает шторку; щипок двумя пальцами — зум (`touch-action: none` на оверлее).
- Липкая полоса вкладок в панели непрозрачная и на всю ширину (`.panel .tabs` с отрицательными полями) — иначе контент просвечивает при прокрутке.
- Отчёт — документная типографика (Georgia для текста, Inter для таблиц, линии только горизонтальные), не копия тёмного интерфейса.

## Движение в интерфейсе (по методичке Эмиля Ковальски, скиллы `~/.claude/skills/emil-design-eng`, `review-animations`)

- Кривые и длительности — только токены из `:root` в `style.css`: `--ease-out` (вход/выход), `--ease-in-out` (перемещение на экране), `--dur-press` 160 мс, `--dur-ui` 200 мс, `--dur-modal` 240 мс. Новые `cubic-bezier` руками не писать.
- Что **не** анимируем — и это осознанно: таймлайн, play/pause, выбор пункта/этапа, переключение вкладок панелей (частые действия — анимация делает их медленными); скачок маршрута на сцене (это реальное переключение, его надо видеть резко); тултип спутника (без задержки).
- Появление/скрытие через атрибут `hidden` анимируется парой `@starting-style` + `transition: … display <dur> allow-discrete` и правилом `.x[hidden] { … }` для выхода (модалки, меню «Выгрузить», тост). Выход всегда короче входа (160 vs 240 мс) и в ту же сторону, откуда элемент пришёл. В браузерах без `allow-discrete` элемент просто появляется мгновенно — это допустимо.
- Нажатие: `:active { transform: scale(.97) }` на `.btn`, `.icon-btn`, `.tabs button`, `.seg button`. Анимируем только `transform`/`opacity`: прогресс-бар — `scaleX()`, а не `width`.
- Зум сцены — через цель `state.view.fTarget`; `settleZoom(dt)` в цикле кадров подтягивает `state.view.f` экспоненциально (коэффициент 14/с), поэтому колесо и кнопки прерывают друг друга без рывков. Не присваивать `state.view.f` напрямую — вызывать `zoomTo(f)` / `zoomBy(k)`.
- `prefers-reduced-motion: reduce`: остаются прозрачность и цвет, убираются перемещение/масштаб; в `scene.js` константа `REDUCED_MOTION` отключает автоповорот Земли и делает зум мгновенным.

### Два вида, общие швы

- **`globe.js`** — ресурсы сцены (текстуры Земли, звёзды, модель аппарата, `toThree`, `makeProjector`);
  **`configlink.js`** — формат ссылки `#c=` (включая `hm` рельефа, наклонение плоскости и `dz`);
  **`sync.js`** — связь видов. Правка в любом из трёх задевает и инженерный вид, и вид абонента:
  проверять обе страницы. Копировать код между `scene.js` и `subscriber.js` вместо доработки шва — ошибка:
  числа и картинка разойдутся, а на защите это ловится мгновенно.
- **Пути к ресурсам в `globe.js` — от модуля (`import.meta.url`), не от страницы.** `./vendor/...` сломался бы
  на `/abonent/index.html` (искал бы `/abonent/vendor/`).
- **Вид абонента — «полярная ночь»** (`abonent/style.css`): та же раскладка, что задумана изначально — глобус сверху, под ним лента карточек в одну колонку (телефон в первую очередь, на десктопе колонка 560px по центру). Палитра намеренно не «сине-чёрный дашборд»: тёплый графит `--bg:#0a0908`, тёплый белый текст, связь — аврора `--ok:#5ee6a8`, маршрут — янтарь `--route:#f2b64b`, отказ — коралл `--bad:#ff6b57`; шрифты Unbounded + Golos Text, заголовки обычным регистром. Не переделывать в две колонки и не делать светлым — пробовали, пользователь вернул как было.
  Слова — для жителя, не инженера («Наземная станция», «Сигнал идёт 9 мс», «передаёт ваш сигнал»); тексты в `subscriber.js`. Размер холста глобуса берётся из CSS (`getBoundingClientRect` в `layout()`).
- **Вид абонента не держит шину событий** — у него плоский локальный `S` и один цикл кадров; для одной страницы
  с одним пунктом шина была бы лишней абстракцией.
- **Скорость и момент дублируются в `localStorage` (`aurora.sync.last`), а не только в канал.** Браузер тормозит
  таймеры скрытой вкладки с 250 мс до секунды, а через несколько минут — до раза в минуту; ведомый при этом
  продолжал показывать скорость, которая была на момент переключения (инженер включил ×16, у абонента остался ×4).
  Ведущий пишет `{t, playing, speed, diff, at}` не чаще раза в секунду и **сразу** при смене скорости/паузы/момента
  (`sync.stateChanged()` в обработчиках `#speed`, `#btn-play`, `#btn-now`, `#time-range`); ведомый читает запись
  в `catchUp()` на старте, на `visibilitychange` и `pageshow` и доигрывает время сам. Запись старше двух минут
  (`RESTORE_MS`) не восстанавливается — это уже не «переключился между окнами», а другая сессия.
  Восстановленный такт приходит с `restored: true` и **не** обновляет `S.leaderSeen`: иначе страница врала бы
  «за инженерным видом», когда его окно закрыто. При живом ведущем подпись «за инженерным видом, ×N»,
  при молчащем — «инженерный вид в фоне, ×N».
- **Синхронизация** (ADR-0009): такт `{t, playing, speed}` четыре раза в секунду, конфигурация — по факту
  изменения. Ведомый доигрывает время сам, поэтому каждый кадр шлём не надо. Только один браузер на одной машине.
- **Слияние двух ветвей проекта (2026-09-12).** Ветка с рельефом/конструктором и ветка с видом абонента
  сведены вручную: у общих файлов базой взята ветка с рельефом (там менялась физика), наши правки накатаны сверху.
  Что важно помнить, если придётся повторить: `scene.js` в той ветке отличался от нашей исходной всего в 9 строках
  (наклонение на плоскость + красный пунктир к закрытым аппаратам), поэтому дешевле накатить их на нашу
  развязанную версию, чем переразвязывать `globe.js` заново. Файлы были в CRLF, upstream — LF
  (`.gitattributes`: `* text=auto eol=lf`, `.bat` — CRLF); из-за этого `diff` показывал «все строки разные»
  при идентичном тексте — сравнивать через `diff <(tr -d '\r' < a) <(tr -d '\r' < b)`.
- **Наши ADR пришлось перенумеровать:** 0007 в той ветке занят расширениями схемы, поэтому вид абонента — ADR-0008,
  синхронизация — ADR-0009. Перекрёстные ссылки в доках обновлены.
- **`skyView()` считает углы через `siteFrame`/`lookAngles`**, а не своей формулой — иначе азимут разойдётся
  с тем, по которому `snapshot()` выбирает сектор маски горизонта. Закрытые рельефом аппараты отдаются
  с флагом `blocked`: для жителя «спутника нет» и «спутник за сопкой» — разные ответы.

## Грабли (баг → причина → фикс)

- **У абонента таймер и спутники откатывались назад примерно раз в секунду — но только на публичной
  ссылке, локально всё ровно.** Причина не в деплое и не в service worker: модельное время считалось
  от отрисованных кадров, `state.t += Math.min(0.1, dt) * speed` внутри `requestAnimationFrame`.
  В настоящей фоновой вкладке кадров нет вообще, поэтому часы инженерного вида замерзали, а
  `setInterval` рассылки тактов продолжал работать (браузер тормозит его до раза в секунду, но не
  останавливает) — и уносил в канал мёртвое время. Ведомый жёстко привязывается к каждому такту
  (`S.t = m.t`), между тактами доигрывает вперёд сам — получалась пила: вперёд на ×4, назад к
  замороженному моменту. Локально не видно, потому что оба окна открыты рядом и кадры идут; на
  публичной ссылке «Вид абонента» открывается новой вкладкой **поверх** инженерной, и ведущий
  сразу уходит в фон. Плюс clamp `0.1` врал и без фона: вкладка на 1 fps двигала модель в 10 раз медленнее.
  Фикс — `advanceTime()` в `scene.js` считает дельту по `performance.now()` (троттлинг на это не влияет:
  как бы редко ни позвали, сдвиг равен прошедшему реальному времени × скорость), `setInterval(250)`
  двигает время, пока `document.hidden`, а `getState()` в `app.js` зовёт `advanceTime()` **перед**
  чтением, чтобы такт нёс момент «на сейчас». Clamp остался только для камеры — там большой dt дал бы рывок.
  **Как воспроизвести без настоящего браузера:** встроенный браузер агента фоновые вкладки не тормозит
  (`document.hidden === true`, а rAF всё равно 60 fps — 181 кадр за 3 с), поэтому симптом не появляется.
  Эмуляция в одну строку в консоли ведущего: `window.requestAnimationFrame = () => 0`.
  Замер A/B этим способом: старый код — 12 откатов за 10 с, худший −36 с модели, время топчется
  вокруг одного значения; новый — 0 откатов, часы идут без кадров (683 с модели за 3 реальных против 4 с).

- **Землю нельзя было вращать полосой через верх экрана: курсор становился текстовым и выделял страницу.**
  Причина не в канвасе — `#overlay` там и `cursor: grab`, и `user-select: none`, и `preventDefault()` на
  `pointerdown`. Виноват невидимый стартовый экран: `body.workspace .hero` гасит только сам блок
  (`opacity: 0; pointer-events: none`), а правило `.hero > * { pointer-events: auto }` выше специфичнее
  и возвращает детям попадание курсора. Заголовок, абзац и кнопка «Открыть проект» продолжали висеть
  на `z-index: 5` против `1` у оверлея — полосой `top: 13vh`, шириной `min(720px, 92vw)` по центру.
  Диагностика в одну строку: `document.elementsFromPoint(x, y)` — если сверху не `CANVAS#overlay`,
  значит что-то невидимое перехватывает. Фикс — `visibility: hidden` на `.hero` в workspace (гасит всё
  поддерево сразу и для курсора, и для скринридера) **плюс** явное `body.workspace .hero > * { pointer-events: none }`.
  Второе не избыточно: `visibility` в `transition ... allow-discrete` переключается только к концу
  затухания, а `pointer-events` у детей снимается в тот же кадр, что и класс, — сцена становится
  перетаскиваемой сразу. Проверять фикс не скриншотом, а `elementFromPoint` в шести точках полосы
  и реальным драгом: `state.view.yaw` обязан измениться, `getSelection().toString()` остаться пустым.
  **Общее правило: `opacity: 0` не убирает элемент из hit-testing.** Любой блок, который «просто
  растворяется» поверх сцены, обязан получать `visibility: hidden` или `display: none`.

- **Модальные окна не закрывались / были всегда видны.** `.modal { display:flex }` перебивает UA-стиль атрибута `hidden`. Фикс — глобальное `[hidden] { display:none !important }` в начале `style.css`. Любой новый элемент с `display` в CSS зависит от этого правила.
- **Сцена «сама» отдалялась.** Обработчик `wheel` на оверлее ловил прокрутку, когда курсор над сценой, а пользователь скроллил панель. Панели лежат поверх оверлея, поэтому сейчас конфликт только при курсоре над свободной сценой — это ожидаемое поведение (зум колесом). Если понадобится скролл над сценой — переносить зум на `ctrl+wheel`.
- **Земля тёмная на старте.** Солнце в модели фиксировано в инерциальной системе (`sun_eci`), Земля вращается — в 00:00 UTC освещённая сторона отвёрнута от камеры. Поэтому `state.t` стартует с 43200 (полдень). Не менять на 0 «для красоты» — потемнеет.
- **`heredoc` с обратными кавычками ломает Bash-тул** агента при патчах JS с шаблонными строками — патчи писать в `.py`-файл и запускать его, а не через `<<'EOF'`.
- **`document.write` отчёта в панели предпросмотра** рисует чёрный текст на тёмном — панель форсирует тёмную схему. В отчёте явно `:root{color-scheme:light}` и `body{background:#fff}`.
- **`getBoundingClientRect()` панели предпросмотра** отличается от координат скриншота (масштаб ~2×); синтетические клики через `computer` не вызывают `pointerup` на оверлее — проверять клики по сцене через `dispatchEvent(new PointerEvent(...))`.
- **Панель предпросмотра агента отдаёт `prefers-reduced-motion: reduce`** — в ней видна только упрощённая ветка анимаций (зум мгновенный, тост без сдвига). Полную ветку проверять в обычном браузере или временно переопределив правила медиа-запроса через инжект `<style>`.
- **Тест «липкого» маршрута** нельзя писать на `t=0→120`: S20 уходит из видимости шлюза на первом же шаге. Использовать 120→240.

## Рельеф, местность, конструктор группировки (ADR-0007)

- Видимость: `sinEl ≥ sin(min_elevation)` — правило кейса — и затем, если у пункта есть `horizon_mask`, `sinEl ≥ sin(mask[сектор азимута])`. Закрытые маской аппараты попадают в `snap.ground[id].blocked` — сцена рисует их красным пунктиром к выбранному пункту/шлюзу.
- Источники маски и где они живут: пресеты — `TERRAIN_PRESETS` в `sim.js` (высота застройки/расстояние → `buildingAngle`); реальный рельеф — `data/terrain.js` (ключ `"lat,lon"` с двумя знаками; `demFor(g)` в `model.js`), генерируется `python web/tools/horizon-mask.py` (ASTER GDEM 30 м через OpenTopoData, ~1 запрос/с, ~8 запросов на пункт); по кнопке «запросить рельеф» из браузера — `fetchTerrainMask()` через open-meteo (Copernicus DEM GLO-90). Формула одна — `maskFromProfiles()`; скрипт её дублирует, расхождение — баг.
- **OpenTopoData не отдаёт CORS** — из браузера его не вызвать, поэтому два источника DEM. Не менять `fetchTerrainMask` на OpenTopoData «для единообразия».
- Новый пункт из списка городов получает «рельеф DEM» автоматически, если для его координат есть предрасчёт (`fillTerrainSelect()` в `app.js`); при клике по Земле — открытая местность.
- Конструктор: `walkerDelta()` → `applyDesign()` в `model.js` заменяет `design` целиком, снимает отказы по исчезнувшим аппаратам, `launch_stage` = число очередей. Всё, что предполагало «3 очереди по 16», должно идти через `maxBatch(s)` (кнопки этапов, `deploymentPlan`, `optimizeBatches`, сравнение).
- Сравнение раскладок очередей — `layoutCompare()` (воркер `layouts`): та же группировка с очередями «вперемешку» (`assignBatches(...,'spread')`, размеры очередей сохраняются, полная группировка не меняется) плюс Walker T/P с лучшим F; показатели этапов на полной сетке (~200 мс). Кнопка «Применить» для `spread` меняет только `launch_batch`, для Walker — зовёт `generateWalker`. Вывод для защиты: первая очередь 13% → 31%, перерыв 13 ч → 72 мин; плата — ISL между плоскостями.
- **Свежесть результатов аналитики — не косметика, а корректность.** `state.analysis[type]` хранит `scenarioHash`;
  отчёт читает результаты только через локальный `an(type)` в `buildReport()`, который сверяет отпечаток и складывает
  несовпавшие в `staleTools` — они перечисляются в отчёте отдельной строкой «Не включено в выводы». В интерфейсе
  `markStaleAnalysis()` на `recomputed` вешает `.an-note.an-stale` в контейнер инструмента (реестр `OUT_OF`).
  Было: отчёт цитировал N-1/N-2 прежней конфигурации как обоснование текущей — жюри ловит это одним кликом.
  Новый инструмент обязан попасть в `TOOL_NAMES`, иначе в отчёте он назовётся служебным ключом.
- **`hashScenario()` считается по содержимому (FNV-1a), а не по длине JSON.** Прежний вариант давал одинаковый
  отпечаток для raan 120 и 130 при разнице доступности 3.7 п.п. Порядок ключей в JSON влияет на отпечаток —
  это безопасная сторона: лишний пересчёт, а не устаревшие числа.
- **`validate()` не прерывается на первой ошибке.** Разделы проверяются независимо, диапазон значения — только если
  значение оказалось числом; однотипные сообщения сворачивает `collapseErrors()` («и ещё 15 аппаратов с этой же ошибкой»),
  иначе одна опечатка в id плоскости даёт 16 одинаковых строк и вытесняет остальное. На битом файле было 2 сообщения, стало 10.
  В `\b` регулярках по кириллице границы слова нет (JS считает `\w` только латиницей) — не использовать `\b` в русских шаблонах.
- Стратегии маршрутизации — `STRATEGIES` в `sim.js` (`sticky` / `minhop` / `latency`), пятый аргумент `findRoute()`
  и опция `computeAvailability(s, stepMul, { strategy })`; метрики считает один и тот же код, поэтому колонки сравнимы.
  `routeStrategies()` (воркер `strategies`, вкладка «Качество связи», свой контейнер `#an-strategies-out` —
  `renderQuality()` перерисовывает `#an-quality-out` на каждом пересчёте и стёр бы результат). Доступность у стратегий
  обязана совпадать: путь существует или нет по геометрии сети, а не по алгоритму, — расхождение означает баг в поиске.
- Резервные пути — `backupPaths()` (воркер `backup`, вкладка «Устойчивость») на `routeAvoiding()`: на каждом шаге
  строит маршрут, затем ищет путь в обход всех его аппаратов (полный резерв) и поочерёдно в обход каждого (незаменимые).
  Ключевое разделение: `oneAccessShare` — над пунктом виден один аппарат (лечится покрытием), `chainCriticalShare` —
  узкое звено в середине цепочки (лечится дальностью ISL или вторым шлюзом). C65 на полной группировке: обход 17.1%,
  незаменимый аппарат 82.9%, из них 69.7% — единственный аппарат над пунктом.
- Разбивка отказов по направлениям: `vulnerableSatellites()` возвращает `perClient/affected/worstClient`,
  `pairFailures()` — `worstClient` у каждой пары и `badPairsByClient`. Критерий требует показать, «какие направления
  связи затронуты», а не только минимум по всем пунктам.
- Вердикт сравнения вариантов — `verdictHtml()` в `panels.js`, идёт **до** таблицы: кого брать, на сколько он лучше
  второго и чем за это платим. Там же проверка сопоставимости: разные `horizon_s`/`step_s` или разные исходные
  сценарии дают `.cmp-warn` — кейс требует сравнивать «на одном периоде расчёта», дельты между разными сетками недействительны.
- Подбор проекта — `designSearch()` в воркере (`type: 'design'`): ~200 конфигураций за ~1.5 с на `stepMul=3`; с перебором наклонений ×4. Кнопка «Применить» в результатах вызывает `generateWalker` с числом очередей из поля вкладки.
- Ссылка `#c=`: если состав группировки менялся (другие плоскости) — кодируется весь `design` (`dz`), иначе — как раньше; маски пунктов кейса — `hm`.
- Наклонение плоскости в таблице: пустое поле = общее (`environment.inclination_deg`); `setPlaneParam(id, 'inclination_deg', NaN)` удаляет поле, чтобы экспорт оставался чистой схемой кейса.

- **Одно исключение в кадре убивало сцену навсегда:** `requestAnimationFrame(frame)` планировался в конце тела,
  и при ошибке следующий кадр не назначался — выглядело как «всё зависло», причём без явной ошибки в консоли.
  Теперь `startLoop` планирует следующий кадр в `finally`, а ошибку пишет в консоль.
- **`document.hidden` в панели предпросмотра тормозит `requestAnimationFrame`**, поэтому сразу после `navigate`
  `state.snap` может быть `null` несколько секунд — это не сломанный цикл. Перед проверкой выводить вкладку вперёд
  (`tabs_select`) или читать состояние, а не ждать отрисовки.
- **`hashScenario()` не различает правки одинаковой длины.** Считает `JSON.stringify(scenario).length`, поэтому
  `raan_deg: 120 → 130` даёт тот же хеш, хотя доступность меняется с 63.6% на 68.2%. Нужен отпечаток по содержимому.
- **Результаты аналитики не сбрасываются при смене конфигурации — кроме карты покрытия.** `on('recomputed')`
  в `analysis.js` обнуляет только `state.analysis.coverage`; остальные инструменты живут дальше, а `buildReport()`
  читает их без проверки `scenarioHash`. Провал на защите: посчитать N-2 на одном сценарии → переключиться →
  «Сформировать отчёт» → в выводах цифры от прежнего.
- **Ручное действие пользователя должно быть сильнее периодического такта.** Первая версия ведомого ставила
  `follow = true` в каждом такте — кнопка «Сейчас» срабатывала, и через 250 мс её отменял следующий такт.
  Фикс — флаг `S.detached`.
- **Service worker с cache-first отдаёт старый JS после обновления сайта** — у пользователя новые данные со старым
  кодом и разошедшиеся числа. В `abonent/sw.js` раздельные стратегии: код и разметка «сначала сеть, кеш как запас»,
  неизменяемое (`/vendor/`, картинки, шрифты, glb) — «сначала кеш». При правке `CORE` поднимать `VERSION`.
- **Кеш модулей браузера маскируется под баг в коде:** `does not provide an export named 'X'`, хотя `curl` отдаёт
  файл с экспортом и `node --test` его импортирует. Тем же объясняется `Cannot set properties of null` в `app.js`
  после правки `index.html`: документ старый, код новый. Лечится `tools/serve.py` или `?nocache=1`.
- **`Math.floor(m/60)` + `Math.round(m%60)` даёт «6 ч 60 мин».** Округлять минуты до деления (`minutes()` в `subscriber.js`).
- **Скриншот панели предпросмотра агента закрывает открытую модалку** — проверять её содержимое через
  `javascript_tool`/`read_page`, а не скриншотом; UI-регрессии тут нет.

## Договорённости по данным

- **Базовая доступность в матрице N-1/N-2 (97.1%) не равна показателю пункта на полной сетке (96.7%)** —
  `pairFailures()` считает всё, включая базовую строку, на `stepMul = 3` (1176 прогонов суток: 48 одиночных +
  1128 пар, ~14 с вместо минут). Клетки сравнимы между собой, но не с панелью «Доступность».
  Если кто-то сообщит «цифры не сходятся» — это не баг, и объяснение уже есть в корневом `README.md`, раздел 8.1.
- **Замеры скорости ядра (MacBook, Node 24, для README):** `snapshot` 0.04 мс; сутки 48 КА × 3 пункта ≈ 40 мс
  (не 20, как было написано в ARCHITECTURE.md); покрытие 0.1 с; стратегии 0.2 с; резервные пути < 0.1 с;
  раскладки 0.5 с; уязвимые 1.6 с; Монте-Карло 300 — 3.4 с; подбор проекта (206 конфигураций) 3.8 с;
  N-1/N-2 ~14 с; `optimizePlanes` ~18 с (он идёт на **полной** сетке — самый долгий инструмент).

- **Сетка времени** — только через `timeGrid(s, stepMul)`: отсчёты `0 … horizon − step`, правый конец не включается (720 при шаге 120). Ошибка «+1 отсчёт» уже была — проценты плыли на 0.1 п.п. относительно эталона.
- **Переходы** (`hops`) = рёбра маршрута = аппаратов + 1 — определение из «Описания данных». В интерфейсе слово «хоп» не используем.
- **Выгрузка результата** — `buildResult()` в `model.js`, схема `cosmo-A-result-1.0`: `effective_scenario`, `routes[{t_s, client_id, path}]` (720 × число клиентов; `path` = `[client, ...sats, gateway]` или `[]`), дополнительно `summary`, `time_grid`, `reason` у пустых маршрутов.

- Необязательные поля, которые сервис добавляет в сценарий: `environment.sun_eci`, `environment.eclipse_isl_off`, `ground_sites[].horizon_mask` / `terrain` / `terrain_source` / `h0_m`, `design.planes[].inclination_deg`; `launch_batch` — любое целое ≥ 1 (ADR-0007). `validate()` проверяет их только если они есть; в экспорт попадают только заданные.
- Резервные аппараты получают id `SP1`, `SP2`, … и `launch_batch: 1`; добавленные шлюзы кликом — `G2`, `G3`, …
- **Окна связи для абонента** — `contactWindows(s, clientId)` в `sim.js`: окна и перерывы встык покрывают
  горизонт, у перерыва названа причина, `availability` совпадает с `computeAvailability()` по построению.
  Рельеф и наклонения плоскостей учитываются сами — они внутри `snapshot()`. Тест это проверяет.
- **Доступность не зависит от липкости маршрута.** Если прежний путь валиден — путь существует; если нет — BFS найдёт
  любой существующий. Липкость меняет переключения, переходы и задержку, но не «есть маршрут или нет».
- Варианты хранятся в `localStorage` под ключом `aurora.variants.v1`; при смене формата варианта менять суффикс версии.
- Ссылка `#c=` кодирует дифф к встроенному сценарию (`id`, этап, плоскости, отказы, добавленные/удалённые пункты, добавленные КА, очереди, тень, выбранный пункт).

## Известные ограничения модели

- Орбита на сцене приподнята ×1.42 (ADR-0004); все расчёты — в км.
- Тень Земли цилиндрическая, Солнце неподвижно в течение суток — как `sunlight()` в `geometry.py`.
- Задержка — только по длине пути со скоростью света, без обработки на борту и наземной сети.
- Монте-Карло использует `Math.random()` без сева — два прогона с одними параметрами дают разные цифры. Для воспроизводимости у жюри нужен seed-параметр.
- Оптимизатор состава очередей — жадный плюс структурные кандидаты; глобальный оптимум не гарантирован. Для первой очереди физический потолок ≈30% для худшего пункта: 16 аппаратов в одной плоскости не покрывают три пункта непрерывно, а при разнесении по плоскостям пропадает ISL (соседи только через 22.5°).
